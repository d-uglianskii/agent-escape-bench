# agent-escape-bench

**Какие правила вашего AI-агента обеспечены кодом, а какие держатся на том, что модель послушается?**

Вы написали правила для Claude Code или Cursor: не трогать CI, не править примененные миграции, не читать `.env`. Две команды проверяют, что за ними реально стоит.

- **`aeb verify`** берет каждое правило из `CLAUDE.md`, `AGENTS.md` и правил Cursor и пытается его нарушить: через инструменты Edit, Write и Read и через несколько shell-вариантов того же действия. Каждая попытка уходит в ваши настоящие хуки и проверяется по вашим правилам deny и ask. Итог по каждому правилу: обеспечено полностью, частично, только ревью при мерже или только текстом.
- **`aeb bench`** меряет, насколько крепок ваш shell-хук: 164 команды, из них 123 известных способа все-таки сделать запрещенное и 41 обычная команда, которая должна работать.

**Ничего не выполняется.** Обе команды создают одноразовый репозиторий, отправляют каждое действие хукам так, как это сделал бы агент, и записывают ответ: allow, ask или deny.

## Установка и запуск

```bash
pipx install git+https://github.com/d-uglianskii/agent-escape-bench
# без pipx: git clone репозитория и запуск "python3 -m agent_escape_bench ..." из него
cd your-repo

aeb verify .             # попытаться нарушить каждое правило из ваших инструкций
aeb verify . --plugin DIR  # то же, с хуками плагина Claude Code
aeb bench --claude .     # PreToolUse-хуки на Bash из .claude/settings*.json
aeb bench --cursor .     # beforeShellExecution-хуки из .cursor/hooks.json
aeb scan .               # быстрая статическая карта: к каким правилам вообще привязан механизм
```

Нужен Python 3.9+, зависимостей нет. Отчеты: `--md`, `--html`, `--json`. Для CI: `aeb bench --max-escapes 0` и `aeb verify --max-obedience 0`.

## Что делает verify

Для правила про путь (CI, настройки агента, миграции, lock-файлы, сгенерированный код) пробы такие: инструменты Edit и Write, shell `>>`, `cd` и `>`, `sed -i`, `python3 -c`. Для `.env`: Read, `cat`, `grep`, `python3 -c`. Для force push, пропуска git-хуков, разрушительных команд и новых зависимостей: по три shell-варианта. Команды, которые правило прямо называет в обратных кавычках под «запрещено» или «никогда», проверяются как есть. К каждому правилу добавляется контрольное действие, которое должно проходить, чтобы было видно, если механизм блокирует вообще все.

Хуки запускаются по-настоящему. Правила permissions вычисляются по модели, написанной по документации Claude Code, а не самим Claude Code. CODEOWNERS показывается как гейт при мерже. Вердикты предполагают агента, который работает без подтверждения каждого действия (acceptEdits, auto mode или широкие allow-правила). В обычном режиме Claude Code спрашивает перед каждой правкой и всегда спрашивает про свои защищенные пути (`.claude`, `.git`, `.husky` и другие); отчет такие пути помечает.
